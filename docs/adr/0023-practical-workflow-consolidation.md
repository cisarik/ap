# ADR-0023: Practical Workflow Consolidation

Status: Accepted

Date: 2026-09-11

Artifact relationship: **historical** design rationale; retained evidence for AP
maintainers and consumers. [AP.md](../../AP.md) remains the sole live semantic
owner; [PROMPT_CONTRACTS.md](../../PROMPT_CONTRACTS.md) owns exact structural
spellings. Replaced rationale stays in Git history; retirement requires a
separately authorized lifecycle change.

## Context

The accepted repository-grounded plan compared the practical workflow requests
with AP baseline `7ef45da756ed3cc14808e89bf25d0a9f9aba5d26`. AP already provided
bounded grants, finite planning and acceptance, three roles, session coordinates,
proportional evidence, and a reading spine. The remaining friction concerned
delivery defaults, access-profile names, oversized common reading, exclusive
trace persistence, and confusing a native plan or foreign artifact with a report.

The Cooperator accepted consolidation and then explicitly corrected handout
authorship to include an assigned Worker or the Cooperator. Acceptance of this
architectural decision records that design choice. It does not assert independent
acceptance of the resulting implementation candidate, publication, consumer
adoption, or logical-whole closure. Those retain their applicable AP grants and
evidence requirements; the historical status creates no additional ceremony.

## Decision

Keep the existing semantic owner and operational/structural projections. The
coherent change covers:

1. Orchestrator and ChatOrchestrator access profiles, with dispatch capabilities
   and local/public observation boundaries recorded separately.
2. Three persistent roles; Planner and functional specialists as WORKER profiles
   or capabilities.
3. A first manual native Planner for each new whole, then one preserved
   Cooperator-selected manual/subagent delivery route.
4. Additional bounded technical planning with truthful prior-decision fields and
   no budget reset for the same question.
5. A visible delivery capsule, reasoning/context recommendations, and explicit
   client mode; presentation and telemetry remain distinct from authority.
6. Exact, separately authorized Planner/Worker artifact persistence.
7. Separate authorship, persistence, reconciliation, and Git ownership; report
   identity and interruption separation; native-client completion without replanning.
8. Trace-local notes and shared handoff/closure numbering, truthful handout
   authorship, explicit predecessors, and continuity of an already planned whole.
9. A compact Worker common foundation with task-relevant verified citations.
10. Causal test selection from a named behavior and evidence gap, including
    read-only acceptance and early use of accepted data-retention decisions.
11. Functional WebSearcher, DeepResearcher, and ImageCreator input/output routes.
12. Compact MEASURED/LEAD critique in terminal reports.
13. Contextual option selection, Continue, and brainstorming within existing
    authority, preserving Worker expiry and complete renewed grants.

Each changed normative obligation has one existing detection class and a named
surface in AP. Actual initial native delivery, actual reading, actual Deep
Research activation, and contextual conversation behavior remain behavioral
obligations; metadata cannot mechanically prove them. Projections link to these
owners rather than becoming additional live rules.

## Alternatives and Dispositions

Retaining automatic agent dispatch conflicts with the accepted first-Planner and
preserved-route decision. Treating access as dispatch capability obscures evidence
limits. Exclusive Orchestrator file persistence creates avoidable courier work;
unbounded Worker archival instead would conflate writing, reconciliation and Git.
The selected design permits only exact named preparation and preserves the
after-outcome first-add transaction.

An orchestration register, mandatory overhead record, protocol rename, universal
word cap, mechanical prose validator, fixed context threshold, numeric tier-spread
split, and mandatory separate testing Worker lack a demonstrated need. Existing
routing, validation, and compact reporting records suffice. Self-review remains
useful without becoming independent acceptance; manual delivery alone is not proof
of independence. Development status does not authorize data purging. Historical
search inventories establish their stated coverage, not universal absence.

A generic in-band additive amendment using unchanged exchange coordinates is
deferred because concurrent effects and changed assumptions need safe re-gating;
use a complete compact renewed grant to the healthy current Worker instead.
Delegating Workers remain accountable for one consolidated report and need
explicit delegation/concurrency authority. No historical translation pilot or
unrelated project is reopened. Deferring subjective human acceptance until the
end does not waive technical or independent evidence.

## Partial Supersession and Compatibility

- ADR-0011: replace optional first planning with the initial Planner rule; retain
  risk-sensitive additional planning, finite budgets, and authority boundaries.
- ADR-0014: replace exclusive trace persistence and clarify report/interruption
  identity; retain coordinates, exact history, and atomic first Git archival.
- ADR-0016: extend completion to exact authorized persistence and preserve an
  already selected/planned whole on restoration; retain non-authorizing recovery.
- ADR-0017 and ADR-0020: replace optional-only signaling with a minimum capsule,
  keeping project extensions, proportional cost, and the narrow direct-action boundary.
- ADR-0019: replace Agent/Read-Only labels with access profiles and distinguish
  separate-session freshness from inherited-context independence failure.
- ADR-0021: narrow the common Worker spine and place notes semantics in AP while
  activated local naming belongs to Meta; retain detectability and single ownership.
- ADR-0022: replace default agent dispatch and exclusive Orchestrator archival;
  extend companion identity beyond non-duplication; successor profile is in content,
  with local handout names independent of exclusive authorship.

Earlier ADR bodies, historical reports, filenames, and governing pins retain their
original meaning. New prompts under this revision apply the new rules prospectively;
an already planned whole does not repeat its first Planner. The standard report
header, terminal statuses, three coordinates, and universal unsuffixed exchange-01
grammar remain unchanged. Meta's zero-based filename suffix remains local storage.
No executable, schema, CI, managed-block, runtime, or consumer-pin change is part
of this decision.

## Validation and Consequences

the accepted positive/negative scenarios, changed Markdown links/anchors,

time, token use, or error remain unmeasured until observed in future work.

authorized Cooperator reversal of Meta README. Preserve historical evidence;
consumer pin adoption or rollback is a separate task.
